\begin{abstract}
Reinforcement learning has been increasingly applied to competitive environments in which
an opponent's behaviour is not fixed. When an opponent's behaviour changes abruptly, the
resulting non-stationarity can invalidate a previously effective policy. Hierarchical architectures are widely expected to re-adapt faster
than flat ones in such situations, yet this expectation has rarely been tested
directly against a shifting opponent. This work investigates whether a
hierarchical Feudal Network (FuN) recovers more quickly than a flat Proximal
Policy Optimization (PPO) agent following abrupt opponent strategy shifts in the
game of Go. Both
agents are trained against fixed heuristic opponents in PettingZoo's
\texttt{go\_v5} on $9\times9$ and $13\times13$ boards, after which mid-training
opponent shifts of varying magnitude and frequency are introduced. Their effect
is measured by recovery time, together with the depth and overall cost of the
resulting performance drop, over multiple random seeds. Across the conditions
examined, the hierarchical agent does not recover faster than the flat baseline.
These findings suggest that the FuN hierarchy does not provide
the expected advantage under opponent-induced non-stationarity.
\end{abstract}

\section{Introduction}

%% Motivate: real opponents change strategy mid-interaction - the agent's
%% policy suddenly underperforms and must re-adapt (non-stationarity).
Reinforcement learning (RL) is a framework in which an agent learns how to
behave by interacting with an environment. The agent observes different states, takes actions on those states and receives a reward, gradually adjusting its behaviour to maximise these rewards
it collects over time~\cite{sutton2018reinforcement}. Through repeated trial and
error the agent learns a policy, a function that maps each state to an action. Such a policy works well as long as the environment stays the same, but many real settings are not static. In
competitive games in particular, an opponent does not play the same way forever
and may change its strategy as the game unfolds. When the opponent changes, the
conditions the agent originally learned against no longer hold, so behaviour
that was once effective can suddenly perform poorly. This effect, in which the
environment an agent faces shifts because the opponent's behaviour changes, is
known as non-stationarity~\cite{padakandla2022survey}. This is the central
difficulty this work addresses. An agent that cannot adjust quickly after such a
change, suffers a lasting drop in performance, which motivates investigating how the
architecture of a learning agent affects how quickly it recovers once an
opponent shifts strategy.

%% The idea under test: a manager/worker hierarchy should recover faster.
A learning agent is commonly implemented as a flat policy, which is a single network that maps observations directly to actions. A widely used example of this design is Proximal Policy Optimization (PPO)~\cite{schulman2015trust}. When the opponent shifts, a flat agent has to
revise this single policy as a whole, which can be slow and risks overwriting
behaviour that is still useful. An alternative design is a hierarchical agent, which
splits decision-making across levels. The Feudal Network (FuN)~\cite{dayan1993feudal, vezhnevets2017feudal} is one instance of this structure, in which a high-level manager sets goals over a longer timescale while a low-level worker chooses the primitive actions that pursue them. The idea this research tests is that this hierarchy should recover faster after an opponent changes strategy. The manager can switch to a new high-level plan while the worker keeps the low-level skills it has already acquired, so less has to be relearned than in a flat agent. However, this advantage has largely been demonstrated for adaptation to new tasks rather than to an opponent that changes strategy during game-play.

\subsection{Research Question}

The gap of whether the hierarchical structure of learning agents adapts to changing strategic opponents motivates the central research question of this work: \emph{Does a
feudal reinforcement learning improve recovery time following abrupt opponent
strategy shifts, compared to flat RL approach (PPO)?} The question is studied in
the board game Go, where a hierarchical Feudal Network and a flat PPO agent are
each trained against fixed heuristic opponents and then subjected to abrupt
strategy shifts, on two board sizes, $9\times9$ and $13\times13$.

%%  \item What this work adds: (i) a controlled opponent-shift recovery
%%        benchmark in Go; (ii) a tested FuN vs PPO comparison under identical
%%        conditions, across shift magnitude, frequency and board size, (iii)
%%        three recovery measures and what each can and cannot detect.
The study is built around three main elements. First, a controlled benchmark is
developed for measuring recovery from opponent strategy shifts in Go. The timing, magnitude and frequency of each shift are fixed in advance so that recovery can be measured cleanly. Second, a Feudal Network and a flat PPO agent
are compared under identical conditions, matched across shift magnitude,
frequency and board size. Any difference in recovery therefore reflects the architecture rather than the experimental setup. Third, recovery is assessed
using four complementary measures, each capturing a different aspect of the
process. Altogether, these measures provide a clear and controlled test of recovery.

%% Main finding: the hierarchy did not improve recovery.
The question this work pursues is whether the structure of the learning agent
governs how quickly a policy recovers once a shift in an opponent's strategy has
left it ineffective. A flat PPO agent and a hierarchical Feudal Network are trained to a
common standard, then exposed to the same abrupt opponent shifts under matched
conditions in Go. This yields a direct test of whether the recovery advantage expected of hierarchy holds when the disruption comes from a shifting opponent rather than a new task. The study finds that this advantage does not
materialise. The sections that follow develop this result and examine why it
arises.

How far an agent's performance falls when an opponent shifts strategy, and how
quickly it recovers, depends both on the nature of that change and on how the
agent itself is organised. This section reviews the research behind this,
building from the background of reinforcement learning in Go to the mechanisms
by which a strategy shift disrupts a learned policy and an agent's design shapes
its recovery. It begins by setting the scene with Go and the reinforcement
learning results achieved on it. Secondly, it considers how a shifting opponent gives rise to non-stationarity
and why this undermines a previously learned policy. Thirdly, it goes on to review flat
and hierarchical reinforcement learning, introducing the PPO agent and the Feudal
Network that this study compares. Finally it turns to how adaptation and recovery
have been measured, which frames the metrics used and leads to the
gap the work sets out to address.

\subsection{Reinforcement Learning in Go}
Go is an ancient two-player board game that originated in China more than two
thousand years ago and is still widely played. The players take turns placing
black and white stones on the intersections of a square grid. Both players can see the whole board at all times, so no
information is hidden from either side. A stone or connected group is captured
and removed once opposing stones occupy every point beside it. The winner is the
player who controls the larger share of the board at the end. This is decided by
area scoring, which counts both the territory a player surrounds and the stones
it has in play~\cite{silver2016mastering}. Moving first is an advantage, so a
fixed number of points called komi is added to the second player's score to keep
the game balanced. Play continues until both players pass in succession, by which point a typical
game has run to a few hundred moves.

Although its rules are simple, Go is extremely hard to play well. For many years
this difficulty made it a landmark challenge for artificial intelligence. At each
turn a player has a very large number of legal moves to choose from, and a full
game lasts hundreds of turns, giving Go a space of possible games far larger
than in chess~\cite{silver2016mastering}. Playing well is not only about the current move.
It also demands long-term planning, since a stone placed early can prove decisive
many moves later. The search-based programs that had already mastered chess could
not cope with this scale, as there are far too many moves to examine~\cite{campbell2002deepblue}. Progress
instead came from reinforcement learning, in which an agent improves by playing
the game and learning from the outcomes rather than by searching through every
possibility.

The breakthrough came with AlphaGo, which combined neural networks with
look-ahead search and millions of games of self-play to beat a professional
human player~\cite{silver2016mastering}, a milestone that drew broad attention
to reinforcement learning. The field has since spread well beyond board games to
real-world problems, where the conditions an agent faces rarely stay the
same~\cite{padakandla2022survey}. Systems like AlphaGo, though, were trained under
stable conditions, improving against themselves or against fixed opponents rather
than against an opponent that changes strategy midway through a game. This study
uses Go differently. Go is a game of perfect information, with no hidden state or
element of chance. Any difference in how two agents handle a mid-game change of
opponent can therefore be traced to their architecture, and not to luck or to
information they could not see.

%% non-stationary and why shifts effect policies
\subsection{Opponent-Induced Non-stationarity}
\subsubsection{Non-stationarity from a Changing Opponent}
In standard reinforcement learning the environment is assumed to be stationary.
Its transition and reward dynamics stay fixed throughout
learning~\cite{sutton2018reinforcement}. When
an agent trains against an opponent, that opponent's behaviour becomes part of
the dynamics the agent learns to exploit. If the opponent later plays
differently, those dynamics change, and the experience the agent has gathered no
longer describes the game in front of it~\cite{littman1994markov}. This shifting
of the environment is what is meant by non-stationarity, and learning to cope
with it has been a recurring focus of reinforcement learning
research~\cite{busoniu2008overview, padakandla2022survey}.

\subsubsection{Why a Strategy Shift Breaks a Learned Policy}
A policy is only as good as the conditions it was trained under. Through repeated
play the agent settles on actions that worked well against the previous opponent,
together with value estimates that reflect how that opponent responded. When the
opponent shifts, the same positions begin to arise from different play. Actions
that were once rewarded may no longer be. The agent's value estimates also stop
matching what it now observes. Performance therefore drops at the moment of the
shift, sometimes sharply. The metric only recovers once the agent has gathered enough
experience of the new opponent to correct its policy~\cite{he2016opponent}. The speed of that recovery is the central concern of this work. It is shaped in large part by how the agent
is built.

\subsection{Flat and Hierarchical RL}
%%Flat on-policy RL: PPO - the baseline under test.
\subsubsection{Flat Policies and PPO}
The simplest way to build a learning agent is as a flat policy. A single network
maps each observation directly to a choice of action, with no internal division
of the decision into levels. Proximal Policy Optimization (PPO) is a widely used
method of this kind~\cite{schulman2015trust}. PPO is an on-policy algorithm that
improves the policy in small steps to keep training stable. This design is simple
and effective, but it holds all of the agent's behaviour in one set of
parameters. When the opponent shifts, the agent cannot change part of its
behaviour while keeping the rest fixed. It must revise the whole policy at once.
Useful skills can be overwritten in the process. This is the weakness that a
hierarchical design sets out to avoid.

%% Hierarchical RL and Feudal Networks: Manager--Worker, temporal abstraction, intrinsic sub-goal reward; note the claims that it adapts to a different opponent.
\subsubsection{Hierarchical Reinforcement Learning and Feudal Networks}
Hierarchical reinforcement learning takes a different approach, dividing control
across two levels of decision-making~\cite{pateria2021survey}. A
high-level policy plans over the long term by setting sub-goals, while a
low-level policy chooses the individual moves that work towards them and is
guided by an intrinsic reward for reaching each sub-goal~\cite{kulkarni2016hierarchical}.
A single sub-goal covers many moves, so the high-level policy sets far fewer
sub-goals than the low-level policy makes moves. This compression of the problem is known as temporal
abstraction~\cite{sutton1999between}. The Feudal Network (FuN) is a neural
instance of this idea, built on early feudal reinforcement
learning~\cite{dayan1993feudal}. A Manager sets a high-level goal at intervals and a
Worker acts at every step to follow it~\cite{vezhnevets2017feudal}. This
separation is what makes the structure appealing for a changing opponent, since
the Manager can adopt a new plan while the Worker keeps its low-level skills.

\subsection{Measuring Adaptation and Recovery}
%% Recovery-time / adaptation-speed metrics; how the recovery measure relates and contrasts with catastrophic-forgetting work.
\subsubsection{Adaptation and Recovery metrics}
The effect of a change is measured by how quickly an agent returns to its former
level of performance, usually called recovery time or adaptation
speed~\cite{alshedivat2018continuous}. This is related to work on catastrophic
forgetting, but the two differ. Forgetting concerns how much of a previously
learned skill is lost when a network is trained on a new
task~\cite{kirkpatrick2017overcoming}. Recovery instead concerns how quickly
current performance returns once a single opponent has changed. This study tracks
performance as a rolling win rate over a fixed window of games. Recovery is
measured as the number of games the win rate stays below a set fraction of its
pre-shift value, together with how far the win rate falls and how much is lost
while it remains below. These measures are defined in full in the experimental design to follow.

%% State the gap this paper fills: HRL vs flat recovery under an opponent shift, tested directly.
\subsubsection{Recovery Under an Opponent Shift}
This section has traced how a changing opponent creates non-stationarity. It has
contrasted flat and hierarchical agents and shown how recovery is measured. These
lines of work have not yet been brought together.
How a hierarchical agent recovers when an opponent changes strategy has rarely
been examined directly. It has seldom been set against a flat agent under matched
conditions. This study provides that comparison, using recovery from a controlled
opponent shift in Go as its test.

\subsection{Environment and Opponents}
%% \textbf{Environment:} PettingZoo \texttt{go\_v5}; $9\times9$ (komi 5.5) and $13\times13$ (komi 7.5); area scoring. Note the move-cap / forced-termination handling.

\subsubsection{Environment}
All experiments are run in \texttt{go\_v5}, the Go environment from the PettingZoo
library~\cite{terry2021pettingzoo}, which provides a standard and reliable
implementation of the full rules of play. In each game the trained agent controls
one colour while a fixed opponent controls the other. Two board sizes are studied as seen in Figure~\ref{fig:boards}. The first is a $9\times9$ board
with a komi of 5.5 and the second is a $13\times13$ board with a komi of 7.5. These
sizes balance strategic depth against the cost of training, since a smaller board
shortens each game and allows many more to be played within a fixed budget of
training steps. Komi
adds a fixed number of points to the second player's score to offset the
advantage of moving first.

\begin{figure}[H]\centering
  \includegraphics[width=0.6\linewidth]{figs/fig_boards.png}
  \caption{The two board sizes illustrated in PettingZoo \texttt{go\_v5}.}
  \label{fig:boards}
\end{figure}

At each turn the agent receives the board as a stack of seventeen binary planes of
size $N\times N$, where $N$ is the board dimension (9 or 13). These planes record
the stones of both players over recent moves along with the colour to
play~\cite{silver2017mastering}. This is illustrated in Figure~\ref{fig:obs-encoding}. For the agents own move it chooses among the $N\times N$ intersections or a single pass.

Two design choices ensure that every game ends in a clean, decisive result.
First, the opponents are built to keep playing while worthwhile moves remain,
rather than passing early. In Go the game ends as soon as both
players pass in succession, and the board is then scored exactly as it stands. An
opponent that passed while territory was still contested would therefore end the
game on an unfinished position, so the result would hinge on the arbitrary moment
it chose to stop rather than on how well either side had played. By playing the position out, each
opponent forces a full contest for territory, so the agent must genuinely control
more of the board to win. Second, we impose a fixed cap on the number of moves
per game. This prevents the rare case where two deterministic players could
continue indefinitely under area scoring. When the cap is reached, both players
are forced to pass, so the environment always returns a final score. Together
these choices give every game a clear area result, which provides the consistent
performance signal the recovery analysis depends on.

%% \textbf{Fixed opponents:} five heuristic bots (greedy, defensive, corner, edge, random), description of each style.
\subsubsection{Fixed Opponents}

The agents are trained against a set of five fixed opponents, each following a
simple hand-coded strategy. Every opponent plays deterministically and reacts
only to the current board, so its behaviour is stable and repeatable. This makes
it possible to switch opponents at set points during training and to be confident
that any resulting change in the agent's performance stems from the switch itself,
not from variation in how the opponent plays.

The five styles differ in what they value, summarised in Table~\ref{tab:opponents}. The greedy opponent takes the largest
available area on each move and captures only when a capture is offered. It does
not hunt the agent's stones, so it tends to build thin, loosely held positions.
The defensive opponent focuses on its own groups, connecting stones and
protecting liberties while avoiding unnecessary contact. The corner opponent
plays sound contact moves with a soft lean towards one corner of the board. The
edge opponent behaves similarly but leans towards the sides. The random opponent
selects a legal move uniformly at random on every turn. It serves as a baseline
with no strategy at all. The four strategic opponents are deliberately imperfect.
They follow their chosen style but do not avoid basic tactical mistakes, which
keeps each one beatable by a trained agent. Figure~\ref{fig:opponents} shows a
representative position for each style. The move-density heatmaps in Figure~\ref{fig:opponent-heatmaps} make each style
clearer still, showing where each opponent tends to place its stones over many
games.

\subsection{Agents}
%% \textbf{Agents:} PPO (action-masked categorical policy, shared CNN backbone); FuN (matched CNN perception, Manager dilated-LSTM trained on extrinsic reward, Worker trained on intrinsic cosine reward). State that both share observation preprocessing and backbone so the comparison is architectural; note key implementation corrections made to FuN.
Two agents are compared, a flat agent and a hierarchical one. Both take the same
board observation and pass it through the same lower network. This shared network,
called the backbone, is a convolutional neural network (CNN) that converts the raw board into a compact internal
representation. They also share the same observation preprocessing. The only
difference between them is the structure placed on top of this backbone. Any
difference in behaviour can therefore be attributed to the architecture rather
than to the input or the backbone itself. Figure~\ref{fig:agents} below shows an example of the two different agents architecture.

\begin{figure}[H]\centering
  \includegraphics[width=\linewidth]{figs/fig_agents.png}
  \caption{The two agents architecture}
  \label{fig:agents}
\end{figure}

\subsubsection{Flat Agent (PPO)}
The flat agent is a single network trained with Proximal Policy
Optimization~\cite{schulman2015trust}. \footnote{The PPO
implementation is adapted from
\url{https://github.com/adi3e08/PPO}.} The CNN backbone converts the board into an
internal representation. From this representation the network produces two
outputs. The first is a probability distribution over the possible moves, which
the agent samples to decide where to play. The second is an estimate of how
favourable the current position is, which guides learning. Before a move is
sampled, illegal moves are removed so that only legal placements or a pass can be
selected~\cite{huang2022masking}. Due to everything sitting in one network, a change in strategy has to be
learned by updating the whole policy at once.

\subsubsection{Hierarchical Agent (Feudal Network)}
The hierarchical agent is a Feudal Network~\cite{vezhnevets2017feudal,
dayan1993feudal}. \footnote{The Feudal Network implementation is adapted from
\url{https://github.com/lweitkamp/feudalnets-pytorch}.} It shares the same backbone as the flat agent, then splits into
a Manager and a Worker. The Manager acts less often and sets a goal as a direction
in the network's latent space. It uses a dilated long short-term memory network, known as a dilated LSTM,
which retains information over many steps~\cite{hochreiter1997lstm}. From this alone it learns the game outcome. The Worker acts at every step. It selects the move
that best follows the Manager's current goal. It is trained by an intrinsic reward
that measures how closely the change in the agent's state matches the direction
the Manager set. Due to this signal arriving at every step, the Worker keeps
learning even though the game's own reward comes only at the end.

Several corrections were needed before the hierarchy trained correctly.  In the
implementation inherited at the start of the study, the Manager's goal was
detached from the computation graph on every step. This removed the gradient the
Manager needs to learn useful goals, so the hierarchy stayed inactive. The same
handling also limited the dilated memory to a single step. Once the goal gradient
and the recurrent memory were restored, the Manager began to set meaningful goals. Beyond these corrections, both agents' hyperparameters were tuned for stable
training. The key settings are listed in Table~\ref{tab:hyperparams}.

%% \textbf{External reference:} GNU~Go, to reference agent strength before the comparison.
\subsubsection{External Reference (GNU Go)}
The five heuristic opponents are custom and deliberately imperfect, so they give
no absolute sense of how strong the trained agents are. As a reference point, GNU
Go is played against each opponent. GNU Go is an established rule-based engine that
plays Go without learning~\cite{gnugo}. On both board sizes it beats every
opponent by a wide margin (Table~\ref{tab:gnugo}), which fixes a strong upper reference for play against
them. The trained agents are then read against this reference. It shows whether
each agent reaches the level of a competent engine on the same opponents, or falls
short.

%% \textbf{Phase 1:} train each agent against each opponent to a stable win-rate baseline; this baseline defines the recovery target.
\subsubsection{Phase 1: Baseline Training}
Phase 1 measures how well each agent can learn to play a single fixed opponent.
Each agent is trained from scratch against each of the five opponents, one
opponent per run, so no run mixes opponents. Both agents use identical training
settings and the same step budget, so the only difference between them remains the
architecture.

Performance during training is tracked as a rolling win rate over recent games.
This win rate climbs as the agent learns the opponent, then settles once further
gains are small. The settled value is taken as the agent's baseline against that
opponent. This baseline sets the target for Phase 2, where the same agent must
recover to it after the opponent changes.

\subsubsection{Phase 2: Opponent Shifts}
Phase 2 introduces the abrupt opponent shifts the study is built around, shown as
part of the pipeline in Figure~\ref{fig:pipeline}. Each run resumes a stable
Phase-1 checkpoint, so the agent begins from a known baseline against a known
opponent. Partway through, that opponent is replaced by a different one. Every
shift is between two opponents that both agents can already beat, so a drop in
performance reflects the disruption of the change itself rather than a jump to an
unbeatable opponent. Training continues after the shift and the agent is left to
recover on its own.

\paragraph{Shift magnitude.} Three magnitudes are used, set by how much disruption
each one causes rather than by any fixed rule. The size of a shift follows from how
far apart the two opponents' styles are. A LOW shift moves from the corner opponent
to the edge opponent. Both actively contest position and differ only in the region
of the board they favour, so the change is small. A MED shift moves from the corner
opponent to the defensive opponent. This replaces an aggressive, position-fighting
style with a cautious one that consolidates its own groups and avoids
confrontation. A HIGH shift moves from the greedy opponent to
the defensive opponent. The greedy opponent seizes the largest open areas of the
board, while the defensive opponent holds firm and refuses exchanges. The two
therefore demand very different responses, which makes this the most disruptive
shift and the hardest to recover from. Table~\ref{tab:magnitudes} summarises these magnitudes.

\paragraph{Shift frequency.} Frequency controls how often the opponent changes
during a run. A single change tests plain recovery. Repeated changes test whether
the agent can keep adapting when the environment will not settle. Three frequency
levels are studied, labelled f1, f2 and f3. At f1 the opponent shifts once, which
isolates recovery from a single disruption. At f2 it shifts a few times at regular
intervals, so the agent must recover more than once. At f3 it shifts many times in
quick succession, leaving little time to settle between changes. Crossed with magnitude, this gives nine shift conditions. Figure~\ref{fig:shift-schedule} shows the three schedules on the $9\times9$
board.


\paragraph{Design.} Each condition is run for both agents, on both board sizes, and
repeated over three random seeds. Crossing all of these gives 108 Phase-2 runs.
The seeds share the same Phase-1 starting point, so they capture the variability
of Phase 2 rather than of the initial training. Each run records the outcome of
every game. Recovery is then measured from these records, using the metrics
defined in the metrics section to follow.

%% \textbf{Parameters:} exact shift schedules and step budgets.
\subsubsection{Parameters}
Every run is given a fixed budget of environment steps, where one step is a single
move by the agent. The budgets differ by board size because the larger board is
slower to learn. On the $9\times9$ board, Phase 1 trains for three million steps
and Phase 2 for a further 2.3 million. On the $13\times13$ board these rise to five
million and four million, about $1.7$ times larger in each phase. Scaling both
phases together means an agent has a comparable amount of time to reach its
baseline and to recover, whichever board it plays. Without this, recovery on the
slower board could be cut off before it finished.

A shift schedule lists the opponent the agent faces and the exact step at which
each change happens. Each Phase-2 run loads a Phase-1 checkpoint, then follows its
schedule while training continues. The first change is placed early, once the
resumed agent's rolling win rate has settled back to its Phase-1 level against the starting
opponent. This is at
300\,000 steps on the $9\times9$ board and 500\,000 on the $13\times13$ board. The
three frequencies then differ in how many changes follow. At f1 the opponent
changes once and later changes back. At f2 it changes a few times at even spacing.
At f3 it changes ten times in steady succession. Due to every schedule being fixed
beforehand, both agents and all seeds face exactly the same sequence of changes at
exactly the same steps.



\subsection{Metrics}
%% \textbf{Metrics used:} Rolling win rate (window $100$ games); recovery time; dip depth; adaptation cost. Description and purpose of each metric.
Performance is measured throughout by a rolling win rate. This is the fraction of
the last one hundred games that the agent won. A single game is too noisy to read
on its own, so the rolling average gives a stable signal. The value of this signal
on the game just before a shift is taken as the pre-shift baseline. Recovery is
judged against a band set at $0.8$ times that baseline. A shift counts as a
disruption when the win rate falls below this band. Four further measures then
describe how often a shift disrupts the agent, and what happens once it does.

\paragraph{Recovery time.} Recovery time is the primary measure. It applies the
idea of adaptation speed from earlier work to a shifting
opponent~\cite{alshedivat2018continuous}. It is the number of games the rolling
win rate stays below the $0.8$ band, counted from the game it first drops below to
the game it first returns. A shorter recovery time means the agent re-adapts
faster. If a shift never pushes the win rate below the band, its recovery time is
zero. If the win rate never climbs back above the band, the agent has not
recovered. Recovery time is then counted to the end of that shift's segment.

\paragraph{Dip depth.} Dip depth measures how hard performance falls. It is the
gap between the pre-shift baseline and the lowest rolling win rate reached after
the shift. Large drops of this kind are a central concern when an agent must cope
with a changing environment~\cite{padakandla2022survey}. Dip depth captures
severity rather than speed, so a shift can score a deep dip even when the agent
recovers quickly.

\paragraph{Adaptation cost.} Adaptation cost combines depth and duration into a
single number. It is the total performance lost while the win rate sits below the
baseline, measured as the area between the baseline and the rolling win rate over
the dip. This is a form of the cumulative loss an agent incurs while it
re-adapts~\cite{sutton2018reinforcement}. A deep, short dip and a shallow, long
dip can carry the same cost. It therefore gives an overall measure of the burden a
shift imposes.

\paragraph{Disruption rate.} Not every shift pushes the win rate below the
recovery band: an agent that adapts quickly enough may never dip below its
$0.8$ threshold at all. Disruption rate is the fraction of shifts that do, and
so measures how often an agent is knocked off its baseline in the first place,
rather than what happens once it is. This is a necessary complement to the
other three measures, which are only defined on shifts that already disrupted
the agent: an agent could otherwise score well on recovery time, dip depth,
and adaptation cost simply by rarely being disrupted enough to have them
measured at all. Figure~\ref{fig:metrics} marks all four measures on one real
recovery segment: the point at which the shift first counts as a disruption,
and the recovery time, dip depth, and adaptation cost that follow it.

\end{figure}



\subsection{Tools}
%% \textbf{Setup:} GPU and CPU training on the UCT cluster and CPU training on the CHPC cluster; metrics logged to Weights \& Biases and to per-game CSV files; per-seed runs kept separate then merged; state the number of seeds.
Both agents were implemented in PyTorch~\cite{paszke2019pytorch} and shared a
single training pipeline. Training was carried out on two high-performance
computing clusters. The University of Cape Town cluster provided GPU and CPU nodes, as well as the CHPC cluster, which provided additional CPU capacity.

Each run produced two records. The first was a live stream of metrics to Weights
and Biases. The second was a per-game log recording the outcome of every game.
These per-game logs served as the source for all recovery measures, which were
computed offline after training. Every seed was run and stored separately, then
the seeds were merged at analysis time to produce a mean and a standard error.
Three seeds were used for each Phase-2 condition. The full implementation is
available online.\footnote{\url{https://github.com/bradrscott/honours_rl_project}}

\section{Discussion}
\begin{itemize}
  \item Open with: recap what was tested, then interpret the Results.
  \item Does the result answer RQ3 / reject the hypothesis that hierarchy speeds
        recovery?
  \item Analyse \emph{why} the result is negative - candidate mechanisms.
  \item How recovery depends on magnitude, frequency and board size, and what
        the two boards reveal about the metrics themselves (recovery time is
        informative on $9\times9$; dip depth / adaptation cost on $13\times13$).
  \item How the finding aligns with or contrasts the related literature (HRL's
        claimed recovery advantage vs an opponent-shift setting).
  \item \textbf{Implications:} what the negative result means for using HRL
        under opponent-induced non-stationarity, and when a hierarchy might
        still help.
  \item \textbf{Limitations:} all seeds start
        from the same Phase-1 model, so they capture only Phase-2 randomness; win rate used rather than a territory/score
        margin; boards limited to $9\times9$ and $13\times13$, not full-size
        $19\times19$ Go.
\end{itemize}

\section{Conclusions}
\begin{itemize}
  \item Restate the answer to RQ3 in one line [direction known, final numbers
        TBD]: the FuN hierarchy did not recover faster than flat PPO.
  \item Implication for hierarchical RL under opponent-induced non-stationarity.
  \item Future work: more seeds; $19\times19$ board; a territory-margin metric.
\end{itemize}
